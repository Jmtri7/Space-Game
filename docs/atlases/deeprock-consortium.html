cultures.json → deeprock — proposed, not in config

  1. Front-heavy, functional. One dominant forward volume — a crusher jaw or ore scoop — a fat segmented tank body behind it, ancillary boxes clamped on wherever they cleared the load. Never tidy.
  2. Almost no windows. Light is a few harsh floodlamps clustered at the working end. The crew works by them, not by a view.
  3. Hazard, not livery. Trim-yellow striping and chevrons edge every intake, hatch and thruster. Everything else stays bare, seamed, riveted.
  4. Industrial plant that flies. Segment seams and rivet rows on every barrel, a conveyor ridge down the spine, blunt quad-thruster housings. It reads as machinery first.

Wiring in

cultures.json

One entry — name, description, the colour keys shown, a theme string, an interior_decoration generator. Self-contained; assets reference it by key.

ship_types.json + graphics.json

One row per hull. Each ship silhouette here is strokeless and can be extracted into parts via extract_atlas.py / apply_parts.py — add a row to the T table.

outfits & the figure renderer

The recoloured base of each outfit is a graphics.json entry. The signature pieces are baked geometry — the same path as the shipped cultures: a signature function in a deeprock_outfits.py, baked by build_figure_signatures.py into figure_signatures.py, emitted by Person.draw().

system + routine

Deeprock wants a mining-loop routine — run out to a belt, work a rock, haul back to the platform. A culture is half a faction without a system to live in, a pilot roster and an AI routine.

Adding a culture is additive; adding ship types and outfits is not free. A new ship type shows in every shipyard and a new outfit in every outfitter — an old save loading a shop sees the new stock. That's a story-version bump (see SAVE_SYSTEM.md), not a breakage: NPCs and outfits rebuild from story config on load.

Part of Past the Reach — seven proposed frontier cultures. Companion atlases: Common Kit, Sol Federation, Vherathi Concord, Drossholt Company. Same visual system, same strokeless rule, same figure_parts body.
